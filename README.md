# 실시간 채팅 서비스

> [지난 프로젝트 보기](https://github.com/jthugg/websocket-chat)  
> 2년 전, 똑같은 사이드 프로젝트로 여러가지 시도 해보고싶었던 요소를 적용했습니다.
> 이번에는 불필요한 요소를 정리하고, 실제 프로덕션 상황을 가정 해봅니다.

## 0. 개요

디스코드 채팅방을 모티브로 채팅 메신저 서비스를 구현했습니다.

지난번엔 다양한 기술을 시도해봤다면 이번엔, 프로덕션 환경을 고려해

1. 분산 서버간 유실 없는 안전한 정보 전달
2. 서버-클라이언트간 가볍고 안정적인 양방향 프로토콜 설계
3. 현실적인 인프라 자원 활용

세가지에 더 많은 고민을 담아봅니다.

## 1. 핵심 설계 포인트

### 1.1. 서버 프로그램

#### Rest API

- 모듈러 모놀리틱 아키텍처: 컨텍스트간 논리적/물리적 트랜잭션 단위 분리
- 무상태 보장으로 수평확장 가능성 확보
- 유실 없는 이벤트 발행 보장

#### Messaging Gateway

- 유실 없는 채팅 메시지 전달 보장
- 이벤트 소비 멱등성 보장으로 채팅 메시지 중복 전송 방지
- 클라이언트가 선택할 수 있는 다양한 메시지 송/수신 메시지 포맷 지원
  - `TCP Socket`, `Websocket`: 채팅 메시지 송/수신, 서버-클라이언트간 메시지 포맷 정의
  - `SSE`: 채팅 메시지 수신 only

### 1.2. 클라이언트 프로그램

#### 모바일 앱

- 앱 내에서 TCP 소켓 통신으로 서버와 채팅 메시지를 송/수신

#### 웹 앱

- Websocket으로 서버와 채팅 메시지를 송/수신

### 1.3. 가용 인프라 자원

- RDBMS: PostgreSQL:16.x
- Event Broker: Kafka:4.3.x

> **그 외 자원은 활용할 수 없는것으로 간주합니다.**  
> 예를 들어, 백엔드 캐시 레이어는 로컬 캐시를 활용하고,
> 분산된 서버 노드간 캐시 만료 처리 트리거는 Kafka 이벤트로 전달합니다.
